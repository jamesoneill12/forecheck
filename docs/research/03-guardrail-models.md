# Primary-source scan: open guardrail models and frameworks

Date of research: 2026-09-20. Scope: existing deployed open guardrail models/frameworks, benchmarked against our proposed **vendor-neutral, sequence-aware pre-execution risk classifier for AI-agent tool calls** — typed, calibrated per-dimension probabilities across ~11 atomic risk dimensions (prompt_injection_influence, unauthorized_scope, sensitive_data_exposure, untrusted_destination, privilege_escalation, destructive_or_irreversible_action, financial_commitment, external_communication, policy_conflict, suspicious_action_sequence, insufficient_context), with a separate deterministic ALLOW/REVIEW/DENY policy engine.

Method: WebSearch + WebFetch against official docs, HuggingFace model cards, GitHub repos (including direct LICENSE-file fetches), and arXiv papers. Every claim below is sourced with a direct URL. Items that could not be verified are marked **NOT FOUND** with what was searched, never invented.

## Meta: Prompt Guard family

### Prompt Guard (v1): 86M
- Model card: https://huggingface.co/meta-llama/Prompt-Guard-86M
- Released 2024-07-23 alongside Llama 3.1. Multi-label classifier over **benign / injection / jailbreak** — "jailbreak" = attempts to override the model's own system prompt/safety training; "injection" = embedded instructions in third-party/tool-output content trying to hijack the agent. This maps loosely onto our `prompt_injection_influence` dimension only — it does not classify actions, scope, destinations, or sequences at all.
- Base architecture: mDeBERTa-v3-base (86M backbone + 192M multilingual embeddings).
- Reports temperature-adjusted softmax scores but the model card discusses TPR/FPR/AUC, not calibration (no ECE/reliability diagram). False-positive rate 3-5% on out-of-distribution data without fine-tuning — the card explicitly warns generic deployments need per-application fine-tuning.
- No trajectory/sequence concept — scores one text span per call.
- **License**: Llama 3.1 Community License Agreement (gated download, commercial-use restrictions above 700M MAU, "Llama" branding requirements) — not a permissive OSI license.

### Prompt Guard 2: 86M / 22M
- Model cards: https://huggingface.co/meta-llama/Llama-Prompt-Guard-2-86M , https://huggingface.co/meta-llama/Llama-Prompt-Guard-2-22M ; GitHub: https://github.com/meta-llama/PurpleLlama/blob/main/Llama-Prompt-Guard-2/86M/MODEL_CARD.md
- Same DeBERTa-family architecture (mDeBERTa-base for 86M, DeBERTa-xsmall for 22M — both derived from Microsoft's MIT-licensed DeBERTa but redistributed here as fine-tuned weights under the Llama license). Retrained with an energy-based loss and expanded/refined attack data; 86M covers English+non-English, 22M is English-only and smaller/faster.
- Benchmarked via AUC and "Recall @ 1% FPR" (LlamaFirewall paper, arXiv:2505.03574): 86M reaches AUC 0.98 / Recall@1%FPR 97.5% at ~92.4ms; 22M reaches AUC 0.995 / Recall@1%FPR 88.7% at ~19.3ms. No ECE/temperature-scaling calibration study found.
- On AgentDojo, Prompt Guard 2 86M alone reduced attack success rate by 57% with minimal utility loss (same paper).
- **License**: Llama 4 Community License Agreement (gated).
- **Overlap**: covers one narrow slice (`prompt_injection_influence`) of our 11 dimensions, single-shot only, no action/permission/sequence modeling, no calibrated probability.

Output is a first-token "unsafe" probability with no published calibration study across the family.

## Meta: LlamaFirewall (arXiv:2505.03574, https://arxiv.org/abs/2505.03574 / full text https://arxiv.org/html/2505.03574v1; repo https://github.com/meta-llama/PurpleLlama/tree/main/LlamaFirewall; docs https://meta-llama.github.io/PurpleLlama/LlamaFirewall/; PyPI `pip install llamafirewall`)

Published 2025-05, "LlamaFirewall: An Open Source Guardrail System for Building Secure AI Agents," Chennabasappa et al. (20 authors). This is the single most relevant prior-art system to our project because it is explicitly framed around **agent** security rather than plain chat moderation, and combines three scanners:

- **License**: the orchestration framework/code and its evals/benchmarks are **MIT-licensed** (confirmed by directly fetching https://github.com/meta-llama/PurpleLlama/blob/main/LlamaFirewall/LICENSE — MIT, copyright Meta Platforms). Any bundled Llama model weights used as scanners (Prompt Guard 2, or an LLM judge if you pick a Llama model) carry the separate Llama Community License; the framework itself is model-agnostic and can call any LLM as the AlignmentCheck judge — separately confirmed via search: "Evals and benchmarks are licensed under the MIT license while any models use the corresponding Llama Community license" (https://meta-llama.github.io/PurpleLlama/LlamaFirewall/).

### 1. PromptGuard scanner
Wraps Prompt Guard 2 (see above) as a fast BERT-style first-line filter on untrusted input/observation text.

### 2. AlignmentCheck — closest prior art to our `suspicious_action_sequence` / intent-deviation goal
- **What it is**: NOT a trained classifier. It is a **few-shot prompted LLM-as-judge** — "a static prompt template" fed to a capable general-purpose LLM (the paper evaluates **Llama 4 Maverick** and **Llama 3.3 70B**; the framework is model-agnostic, so any sufficiently capable LLM, including non-Llama, can be substituted). The paper explicitly calls it "an experimental few-shot prompting-based chain-of-thought auditor," not a fine-tuned model — there is no dedicated AlignmentCheck checkpoint, no released training data, no training recipe, because there is no training.
- **Unit classified**: the **entire agent execution trace / reasoning trajectory** — it inspects the agent's chain-of-thought and action history for goal hijacking, indirect prompt injection, and misalignment between what the agent is doing and the user's original objective. This is explicitly trajectory-level, not single-action.
- **Output**: structured JSON with three fields — `observation`, `thought`, `conclusion` (boolean true/false for "misaligned detected"). This is a **binary label with a rationale, not a calibrated probability** — no probability field, no confidence score, no calibration methodology (temperature scaling, ECE) is reported anywhere in the paper.
- **Benchmarks**: on AgentDojo, Llama 4 Maverick as the AlignmentCheck judge reduced attack success rate from 0.18 to 0.03 (83% relative reduction); on an internal goal-hijacking benchmark it achieved >80% recall with FPR <4%. Combined with PromptGuard 2, the pair cut ASR to 1.75% (>90% reduction from baseline) at a 6.13% utility cost.
- **Latency**: paper describes "semantic reasoning overhead" (i.e., a full LLM forward pass/generation per check) as materially slower than the BERT-based PromptGuard scanner, but does not give a specific millisecond figure — this is a real cost/latency gap versus a lightweight classifier.
- **Status**: explicitly labeled "experimental" by the authors themselves, even though it shows the strongest efficacy of the three scanners against indirect injection.

### 3. CodeShield
Static-analysis (Semgrep + regex) engine for generated code across 7-8 languages, >50 CWE coverage, two-tier latency (~60ms fast tier, ~300ms comprehensive tier), reported precision 96%/recall 79%. Not a probabilistic risk model; not relevant to the 11-dimension schema beyond `destructive_or_irreversible_action` for code-execution cases.

### Why AlignmentCheck matters most to us, and where it falls short
It is the only widely-known open guardrail that (a) operates over full agent trajectories rather than single prompts, and (b) is explicitly framed as "does this agent's behavior deviate from user intent." But: it is **prompt-engineering on a generic LLM, not a purpose-trained classifier**; it produces a **single boolean conclusion, not calibrated per-dimension probabilities**; it has **one undifferentiated notion of "misalignment"**, not our 11 orthogonal risk dimensions (no separate signal for unauthorized_scope vs. privilege_escalation vs. financial_commitment, etc.); it does not ingest structured identity/permissions/org-policy as typed input (everything is folded into the prompt as free text); and — being LLM-judge-based — it inherits LLM latency/cost per check rather than being a fast pre-execution gate, which cuts against a "pre-execution" classifier design goal. It is real, citable, important prior art for the *trajectory-awareness* idea, but it does not pre-empt the specific contribution we're proposing (typed, calibrated, 11-dimension, sub-LLM-latency classification with a separate deterministic policy layer).

## NVIDIA NeMo Guardrails, Aegis, NemoGuard family

- **NeMo Guardrails** — repo https://github.com/NVIDIA/NeMo-Guardrails, **license confirmed Apache-2.0** via direct fetch of `LICENSE.md` (SPDX-License-Identifier: Apache-2.0). It is a **hybrid rules+model framework**, not a model itself. Rails are authored in **Colang** (1.0 default, 2.0 available), a Python-like DSL for dialogue flows. Per the README (fetched directly): rails "combine multiple approaches" — Colang rule logic, third-party moderation API integration (ActiveFence, PolicyAI), "LLM self-checking" for input/output moderation and hallucination detection, and AlignScore/LangChain-chain integration. **No bundled classifier weights ship with the framework** — it's BYO-model. No native calibrated-probability output; rails resolve to boolean pass/fail per flow. No native cross-call trajectory memory beyond what a developer builds into Colang dialogue state, and that state models *conversation turns*, not typed agent-tool-call sequences.
- **NVIDIA Aegis 1.0 / 2.0**: HF org `nvidia`, e.g. `Aegis-AI-Content-Safety-LlamaGuard-{Permissive,Defensive}-1.0` (2024) and `Aegis-AI-Content-Safety-Dataset-2.0` (paper "AEGIS2.0: A Diverse AI Safety Dataset and Risks Taxonomy," ~2025-04). LoRA fine-tunes of Llama Guard/Llama-2 on NVIDIA's own broadened taxonomy (13 core + 10 fine-grained subcategories in 2.0); ensemble-of-LoRA-experts design; the 2.0 **dataset** (33,416 annotated human-LLM interactions) is openly published on HF even though model weights are gated. Category-level scores, no ECE/calibration study found. Single-turn content safety, not agent-action or trajectory.
- **Llama-3.1-NemoGuard-8B-ContentSafety** (https://huggingface.co/nvidia/llama-3.1-nemoguard-8b-content-safety, directly fetched): the production Aegis-2.0-derived guard model. Classifies against **23 unsafe categories + safe + "needs caution"**. Output is a **discrete safe/unsafe label plus violated-category list, not a probability** — benchmarked via AUPRC/F1/Jailbreak-Resiliency (no numeric values published on the card itself). Deployable as an NVIDIA NIM (TensorRT-LLM-optimized) or HF LoRA adapter. **License**: dual — NVIDIA Open Model License Agreement **plus** the underlying Llama 3.1 Community License Agreement.
- **Llama-3.1-NemoGuard-8B-TopicControl** (https://huggingface.co/nvidia/llama-3.1-nemoguard-8b-topic-control, directly fetched, underlying arXiv:2404.03820): determines on-topic/off-topic against a system-instruction policy. Notably **this model IS dialogue-history aware** — it looks at the system instruction, prior exchanges, and the final user message, not just one isolated message. This is a genuine (if narrow) instance of sequence-awareness among NVIDIA's guard models, but it tracks conversational topic drift, not a sequence of tool-call risk decisions. Same dual license as above.
- **Llama-3.1-NemoGuard-JailbreakDetect**: single-purpose jailbreak classifier, same licensing pattern, no sequence/probability differentiation found.

**Overlap/gap**: NeMo Guardrails' Colang gives a real precedent for a "deterministic policy layer downstream of a probabilistic signal" (matches our ALLOW/REVIEW/DENY separation), and TopicControl demonstrates dialogue-history-conditioned classification is a shipped, real pattern at NVIDIA — but every NVIDIA guard *model* is a single-turn or single-topic content-safety/topic-adherence classifier with a fixed taxonomy, not an agent-tool-call-risk classifier, none report calibration (ECE), and none model identity/permissions/org policy as structured input. Licensing also stacks two non-permissive terms (NVIDIA Open Model License + Llama Community License) rather than a clean permissive license.

- **protectai/deberta-v3-base-prompt-injection-v2** (https://huggingface.co/protectai/deberta-v3-base-prompt-injection-v2): binary SAFE/INJECTION classifier, fine-tuned `microsoft/deberta-v3-base`; the card explicitly states it does **not** detect jailbreaks and is **not** validated on non-English input (narrower scope than Meta's Prompt Guard). **Overlap/gap**: same class as Prompt Guard — single-text prompt-injection/content-policy scanning, covering slices of `prompt_injection_influence` and `sensitive_data_exposure` (via Anonymize/Secrets scanners), but no action/permission/sequence modeling, no calibration guarantee (and now positive evidence of calibration failure under shift), and the flagship framework is **formally archived/unmaintained** as of this scan.

## MCP-Guard

Unlike an earlier pass of this research, **MCP-Guard does exist as a specific, citable academic artifact**: "MCP-Guard: A Multi-Stage Defense-in-Depth Framework for Securing Model Context Protocol in Agentic AI," arXiv:2508.10991 (https://arxiv.org/abs/2508.10991, full text https://arxiv.org/html/2508.10991v3), authors Wenpeng Xing, Zhonghao Qi, Yupeng Qin, Yilin Li, Caini Chang, Jiahui Yu, Changting Lin, Zhenzhen Xie, Meng Han (Zhejiang University, CUHK, Binjiang Institute of Zhejiang University, Shandong University). Initial submission 2025-08-14, latest version (v4) 2026-01-08.

- **Architecture**: three-stage defense-in-depth pipeline — (1) lightweight static scanning for overt/obvious threats, (2) a deep neural detector for semantic attacks, (3) a **fine-tuned E5-based embedding model** achieving 96.01% accuracy on adversarial prompts — culminating in an "LLM arbitrator" that synthesizes the three signals into a final decision.
- **MCP-AttackBench**: an accompanying benchmark of 70,448 samples (augmented via GPT-4) simulating real-world MCP attack vectors.
- **Open code/weights**: **NOT FOUND** — no repository link, license, or open-source release was found in the abstract/paper text, and a targeted GitHub search for the exact paper's artifact turned up no matching repo. Note that the bare name "mcp-guard" is separately used by several unrelated, unaffiliated small GitHub projects (e.g. `SaravanaGuhan/mcp-guard`, `DYNOSuprovo/mcp-guard`, `General-Analysis/mcp-guard`) that are generic MCP-server security scanners with **no connection to this paper** — do not conflate them.
- **Probability/calibration**: not discussed in the available text; only a point accuracy figure (96.01%) is given for the E5 stage.
- **Sequence-awareness**: not established from available text; the described pipeline appears to operate per tool-call/prompt rather than confirmed multi-step trajectories.
- **License**: not applicable / not found (no open artifact to license).

**Overlap/gap**: conceptually the closest academic analogue to a "multi-stage pre-execution classifier for MCP tool calls," and its 96%-accuracy E5 embedding stage is architecturally similar in spirit to a lightweight pre-execution classifier — but it is an unreplicated academic paper with **no available open weights, code, or calibration methodology**, so it cannot currently be adopted, extended, or compared against empirically.

## Invariant Labs — mcp-scan / Invariant Guardrails

- Repo: https://github.com/invariantlabs-ai/mcp-scan. Announced/updated to v0.2 in 2025 ("Track, audit & secure all local MCP traffic with static+dynamic scanning, local guardrails, and customizable policies" — https://x.com/InvariantLabsAI/status/1925515121524105657, blog https://invariantlabs.ai/blog/introducing-mcp-scan). **License confirmed Apache-2.0** by directly fetching `LICENSE` from the repo (copyright Invariant Labs AG, 2025).
- Scans **MCP server and tool definitions** statically for prompt-injection payloads hidden in tool descriptions ("tool poisoning"), rug-pull attacks, and unsafe cross-origin settings (allowlist/trusted-tool-pinning enforcement), and can also proxy **live MCP traffic dynamically** to analyze sequences of tool calls.
- Sibling repo `github.com/invariantlabs-ai/invariant` ("Guardrails for secure and robust agent development," **also confirmed Apache-2.0** via direct LICENSE fetch) provides a **customizable policy DSL for trace analysis** — explicitly described as enabling "deep semantic analysis of interaction traces to detect complex threats like data leaks, **unauthorized tool sequences**, and policy violations." This is real, citable, genuine sequence-awareness over agent tool-call traces, closer to our `suspicious_action_sequence` dimension than almost anything else surveyed.
- Hybrid: rules/static scanners + a customizable policy language + optional semantic/LLM-based checks; not purely one or the other.

**Overlap/gap**: genuinely sequence-aware and MCP/tool-call-native (a meaningful overlap with our project's unit of analysis and one of our named dimensions), fully open under Apache-2.0. But it is oriented at **detecting malicious/poisoned tool definitions and rule-violating traffic patterns** via a policy DSL, not at producing typed, calibrated per-dimension risk *probabilities* across our specific 11 categories, and it does not model identity/permissions/org-policy as first-class structured (typed schema) input the way our design intends — policies are DSL rules a developer writes, not model outputs.

## Guardrails AI, IBM Granite Guardian, Google ShieldGemma, Qwen3Guard, WildGuard, Lakera, Vijil, Arthur Shield, other DeBERTa classifiers

*(This section synthesizes a parallel primary-source research pass; every claim below carries its own citation.)*

### Guardrails AI (core SDK + Hub)
- Repo https://github.com/guardrails-ai/guardrails, **license confirmed Apache-2.0** via direct LICENSE fetch ("Apache License, Version 2.0, January 2004"). SDK first released ~2023, active through 2026.
- A **validator orchestration framework**, not a model: a "Guard" wraps one LLM call and runs pluggable "validators" — regex/PII-NER (Microsoft Presidio), or ML classifiers (secondary LLM call or HF model). ~65 community validators on the Hub (https://guardrailsai.com/hub).
- Relevant validators: `detect_prompt_injection` (Rebuff-based, https://github.com/guardrails-ai/detect_prompt_injection); `Detect PII` (Presidio, optionally GLiNER, https://guardrailsai.com/hub/validator/guardrails/detect_pii).
- As of **2026-08-25**, Hub validators no longer require a Guardrails-Hub API key/login — moved to standalone public PyPI packages (https://github.com/guardrails-ai/guardrails/issues/1560), removing the earlier commercial-gate friction. No separate Hub-server license distinct from the Apache-2.0 SDK was found; the Hub website itself is a hosted directory with its own ToS.
- No identity/permission/org-policy context modeled. No calibrated probability (validators are mostly pass/fail). No sequence-awareness — one-shot per call.

### IBM Granite Guardian
- v3.0 (~Dec 2024) → v3.1 → **v3.2 (2025-02-26, per IBM's Granite 3.2 announcement)** → v3.3 → **v4.1** (https://huggingface.co/ibm-granite/granite-guardian-4.1-8b). Cards: https://huggingface.co/ibm-granite/granite-guardian-3.2-5b , https://huggingface.co/ibm-granite/granite-guardian-3.1-8b , https://huggingface.co/ibm-granite/granite-guardian-3.0-8b. Repo: https://github.com/ibm-granite/granite-guardian.
- Classifies harm (social bias, jailbreaking, violence, profanity, sexual content, unethical behavior, harm engagement, evasiveness), RAG risks (context relevance, groundedness, answer relevance), **and function-calling hallucination** (syntax/semantic errors in tool calls vs. query/tool definitions, evaluated on APIGen/ToolAce/BFCL v2 splits).
- **Important precision**: function-calling-hallucination detection is **one risk dimension inside the general Granite Guardian classifier itself** (3.2+ and 4.1) — there is **no separate standalone "granite-guardian-3.x-function-calling" checkpoint** (searched by that literal name; not found). v4.1 improves function-call-hallucination balanced accuracy from 0.74 to 0.79.
- **License confirmed Apache-2.0** on the model card. Weights+code open; training data only partially public.
- **Probability/calibration**: v3.2 introduced **"verbalized confidence"** — a discrete High/Low tag alongside the Yes/No label — explicitly **not a continuous calibrated probability with reported ECE/temperature scaling**. This is a coarse confidence bucket, not true calibration.
- Benchmarks: aggregate F1 ≈0.784 across harm benchmarks; RAG AUC ≈0.84; function-call-hallucination AUC ≈0.79.
- Unit classified: single prompt/response pair or single agentic step — **not a full trajectory**.
- **Overlap**: closest existing analog to the target system among fully-open, permissively-licensed models — single-action agentic risk classification is present as a named dimension.
- **Gap**: not sequence-aware; confidence is a coarse bucket, not calibrated probability; no separate deterministic policy engine; taxonomy is ~8 harm categories + a few agentic/RAG risks, not an 11-dimension agent-action-specific taxonomy; no identity/permissions/org-policy context.

### Google ShieldGemma 1 and 2
- **ShieldGemma 1** (text, 2B/9B/27B, ~July 2024): https://huggingface.co/google/shieldgemma-9b , https://ai.google.dev/gemma/docs/shieldgemma/model_card_2. Classifies 4 harm types (sexually explicit, dangerous content, hate speech, harassment) on both input and output with direction-specific guideline templates. ShieldGemma-9B: F1 0.828 (prompt) / 0.753 (response).
- **ShieldGemma 2** (images, 4B, ~March 2025, arXiv:2504.01081): https://huggingface.co/google/shieldgemma-2-4b-it. Classifies synthetic+natural images against 3 policies (sexually explicit, dangerous content, violence/gore).
- **No agentic/tool-call variant found for either** — both are pure content-moderation classifiers (text or image respectively), searched explicitly and not found.
- Both compute Yes/No logits (softmax-convertible to a probability-shaped score) but **no ECE/temperature-scaling calibration study** was found in either official card.
- **License**: **Gemma Terms of Use** — not OSI-approved; includes a Prohibited Use Policy, Google's unilateral right to modify terms/restrict access, and a requirement that restrictions pass through to derivatives (ShieldGemma explicitly inherits these terms as a Gemma derivative). https://ai.google.dev/gemma/terms , https://ai.google.dev/gemma/prohibited_use_policy.

### Qwen3Guard (Alibaba)
- arXiv:2510.14276 (https://arxiv.org/pdf/2510.14276), repo https://github.com/QwenLM/Qwen3Guard, blog https://qwenlm.github.io/blog/qwen3guard/.
- Two variants: **Qwen3Guard-Gen** (generative/instruction-following framing) and **Qwen3Guard-Stream** (token-level classification head for real-time streaming safety **during generation**), sizes 0.6B/4B/8B, 119 languages.
- Classifies 9 categories (violence, non-violent illegal acts, sexual content, PII, suicide/self-harm, unethical acts, politically sensitive topics, copyright, jailbreak) into **3 severity tiers** (Safe/Controversial/Unsafe) — a categorical, not continuous-probability, output; no ECE reported.
- Stream variant is real-time **within one generation's token stream**, not across multiple discrete agent tool calls — a different kind of "sequence" than ours.
- **License confirmed Apache-2.0** on model card (https://huggingface.co/Qwen/Qwen3Guard-Gen-8B).

### WildGuard (AI2)
- Paper arXiv:2406.18495 (2024-06-26, https://arxiv.org/pdf/2406.18495); model https://huggingface.co/allenai/wildguard; data https://huggingface.co/datasets/allenai/wildguardmix, eval mirror https://huggingface.co/datasets/walledai/WildGuardTest.
- 7B (Mistral-based) classifier for three tasks: prompt-harm detection, response-refusal detection, response-harm detection, across 13 harm subcategories.
- Outperforms Llama Guard 2 and Aegis-Guard by up to 25.3% F1 on refusal detection; reduces jailbreak ASR 79.8%→2.4% when used as a moderator.
- **License confirmed Apache-2.0** directly from the HF card frontmatter (`license: apache-2.0`) — note this corrects any assumption that AI2 safety models default to ODC-BY; WildGuard specifically is Apache-2.0 (the underlying WildGuardMix dataset's own license was not independently re-verified).
- Binary yes/no text outputs, not probabilities; no calibration study found. One-shot per prompt/response pair, no trajectory concept.

### Lakera Guard
- Product itself (https://www.lakera.ai/) is **fully closed** — no open weights, no open code, methodology undisclosed.
- The one open artifact: **PINT (Prompt Injection Test) Benchmark**, https://github.com/lakeraai/pint-benchmark — an open evaluation harness + dataset (4,314 inputs: 3,016 English + 1,298 non-English, mixing public/proprietary sources, including injections embedded in long documents), used as a comparison harness across many of the models in this document (deepset's and ProtectAI's DeBERTa classifiers both have PINT example configs in-repo). This is a benchmark methodology, not a model or policy engine.

### Vijil
- Platform has three products: Diamond (agent trust evaluation), Dome (runtime protection), Darwin (automated agent improvement) — https://vijil.ai/platform. Diamond and Darwin are **closed**; only sample/demo repos are public (`vijil-travel-agent`, `agent-audit-samples` — intentionally-vulnerable test targets, not the scoring engine).
- **Vijil Dome is open source, Apache-2.0** (https://github.com/vijilAI/vijil-dome): 20+ content detectors (prompt injection, jailbreak, toxicity, PII) for input/output, **plus tool-level access control and SPIFFE-based workload identity attestation for agents/tools**, with structured audit logging; integrates with LangGraph, Google ADK, Strands.
- **This is the only surveyed open-source project with an explicit, named identity/permission-attestation mechanism for agent tools** (SPIFFE), making it the closest adjacent prior art for the "consumes identity/permissions" half of our design — though it functions as a runtime access-control gate with content detectors, not a pre-execution ML risk classifier producing calibrated per-dimension probabilities across a fixed taxonomy. Diamond (the actual "trust scoring" product) is closed, so its scoring methodology can't be independently verified for calibration or taxonomy design.

### Arthur Shield vs. Arthur Engine
- **Arthur Shield** (https://shield.docs.arthur.ai/, https://www.arthur.ai/built-in-guardrails): commercial, closed-source LLM firewall (PII leakage, hallucination, prompt injection, toxicity via API). No open weights/code, no published technical paper — methodology is opaque and unverifiable.
- **Arthur Engine** (formerly "Arthur GenAI Engine," https://github.com/arthur-ai/arthur-engine, **MIT license**, https://www.arthur.ai/blog/arthur-open-sources-first-real-time-ai-evaluation-engine): a genuinely open-sourced project, but it is a **model/ML observability and evaluation engine**, not a pre-execution agent-tool-call gate — do not conflate it with Shield.
- Neither reports calibration, benchmark, or sequence-awareness claims that could be independently verified in this scan.

### Other DeBERTa-based prompt-injection classifiers
- **deepset/deberta-v3-base-injection** (https://huggingface.co/deepset/deberta-v3-base-injection): binary INJECTION/LEGIT classifier, English+German, fine-tune of `microsoft/deberta-v3-base`. **License MIT**, confirmed via an HF discussion thread applying the license (https://huggingface.co/deepset/deberta-v3-base-injection/discussions/7). The calibration paper arXiv:2606.22659 found this specific model scores **AUC ≈0.500 (chance-level discrimination)** on one adversarial evaluation set — a striking negative data point on out-of-the-box reliability of this class of classifier.
- **protectai/deberta-v3-base-prompt-injection(-v2, -small)** — see Protect AI section above; the arXiv:2606.22659 calibration paper is the strongest available citation that **DeBERTa-class prompt-injection classifiers are demonstrably miscalibrated under attack-distribution shift**, directly supporting "calibration" as a genuine, non-redundant differentiator for our project rather than an already-solved problem.

## What none of these do

Across every project surveyed — Meta's Prompt Guard / Llama Guard / LlamaFirewall (including AlignmentCheck), NVIDIA's NeMo Guardrails / Aegis / NemoGuard family, Protect AI's (now archived) LLM Guard, the MCP-Guard paper, Invariant Labs' mcp-scan/Guardrails, Guardrails AI, IBM Granite Guardian, Google ShieldGemma, Qwen3Guard, WildGuard, Vijil Dome, Lakera/Arthur/other closed products, and assorted DeBERTa injection classifiers — **no surveyed system does all of the following together**:

1. **Classifies a single agent tool call, pre-execution, against a fixed set of ~11 orthogonal, named risk dimensions** (prompt_injection_influence, unauthorized_scope, sensitive_data_exposure, untrusted_destination, privilege_escalation, destructive_or_irreversible_action, financial_commitment, external_communication, policy_conflict, suspicious_action_sequence, insufficient_context) as independent typed probabilities. Every model surveyed either does one dimension (Prompt Guard = injection only; Granite Guardian's function-calling dimension = hallucination/grounding only), a fixed universal content-hazard taxonomy (Llama Guard's MLCommons categories, Aegis/NemoGuard's ~23 categories, ShieldGemma's 4, Qwen3Guard's 9), or one undifferentiated "safe/unsafe" or "aligned/misaligned" verdict (AlignmentCheck).
2. **Reports genuinely calibrated probabilities** (temperature scaling, isotonic regression, or any reported ECE/reliability-diagram evaluation). Every surveyed model that outputs a "probability" is really reporting a raw softmax/first-token logit, an AUC/Recall@FPR operating point, or (Granite Guardian 3.2+) a coarse verbalized High/Low confidence bucket — none publish a calibration methodology or metric, and the one independent calibration study found in this scan (arXiv:2606.22659) demonstrates that DeBERTa-class injection classifiers (ProtectAI, deepset) are **actively miscalibrated under attack-distribution shift**, not merely un-evaluated.
3. **Ingests structured identity, delegated-permission, and organization-policy context as first-class typed input** rather than folding everything into free text handed to an LLM judge (AlignmentCheck), a hand-written DSL rule (NeMo Colang, Invariant Guardrails), or ignoring it entirely (every content-safety classifier). The one partial exception is **Vijil Dome's SPIFFE-based tool/agent identity attestation** — but that is an access-control mechanism, not a typed input consumed by a probabilistic risk model.
4. **Is genuinely sequence-aware across a multi-step agent trajectory while remaining a fast, pre-execution, non-LLM-judge classifier.** The only trajectory-aware system found (LlamaFirewall's AlignmentCheck) achieves this by paying full-LLM-judge latency and cost, is explicitly labeled "experimental," and outputs one boolean rather than calibrated per-dimension scores. NVIDIA's TopicControl model is dialogue-history-aware but tracks topic drift, not tool-call risk. Invariant's mcp-scan/Guardrails is genuinely tool-call-sequence-aware but via a rule-based policy DSL a developer authors, not a learned, calibrated probabilistic model.
5. **Separates the probabilistic risk signal from a deterministic policy engine** as two explicitly decoupled, typed-interface layers. NeMo Guardrails' Colang and Invariant's policy DSL come closest architecturally (a rules/policy layer over pluggable model checks) but ship no bundled agent-tool-call-risk classifier to plug into that layer.
6. **Is fully open at every layer (code, weights, data, and training recipe) under a permissive, commercially-unencumbered license, purpose-built for agent tool-call risk.** The fully-open, permissively-licensed projects (WildGuard, Granite Guardian, Guardrails AI core, mcp-scan/Invariant Guardrails, Vijil Dome, deepset's DeBERTa classifier) are not agent-tool-call-risk-specific; the agent-security-specific projects (LlamaFirewall, NemoGuard, Aegis, MCP-Guard) are either license-encumbered (Llama Community License stacked with NVIDIA's own model license), only partially open (NVIDIA gated weights; MCP-Guard has no open artifact at all), or have gone unmaintained (Protect AI's LLM Guard is formally archived).

This combination — 11-dimension typed calibrated probabilities, structured identity/policy input, genuine multi-step sequence awareness at pre-execution latency, a separate deterministic policy layer, and full openness under a permissive license — is not addressed as a package by any project found in this scan.
